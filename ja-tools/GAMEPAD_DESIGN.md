# ゲームパッド対応 設計(ローカルのタイル版)

本家の DCSS はゲームパッドを扱わない(`windowmanager-sdl.cc` の `SDL_Init` は
VIDEO|TIMER だけ)。ユーザーの変愚蛮怒 SDL2 版のパッド対応
(`C:\Project2\hengband-3.0.2.3-Beta` の `docs/PAD_KEYBIND_DESIGN.md`、
`docs/CURSOR_ONLY_OPERATION.md`、`hd2d/ui/game_pad.h/.cpp`)を手本に、
ローカルのタイル版(SDL)へ入れる。ウェブタイル版・コンソール版には入れない。

## 0. 方針

- **パッドの入力は既存のキー入力として流す。**`SDLWrapper::wait_event` が
  パッドの出来事をキー 1 つの `WME_KEYDOWN` に変えて返す。ゲーム側
  (tilesdl.cc の `getch_ck`、ui.cc の `pump_events`)は何も知らなくてよい。
- 変愚の「落とすと必ず壊れる約束」(`game_pad.h` 冒頭)はすべて守る。
  1. 窓が入力の焦点を持っていないときは方向を出さない。
  2. 焦点が戻った直後・パッドを挿した直後は、一度中立を見るまで方向を受け付けない。
  3. スティックの死区は出入りで別のしきい値(倒した 18000 / 戻した 11000)。
  4. 方向を入れ替えたときもリピートの間隔を置く。
  5. トリガ(LT/RT)は軸。立ち上がり(16000)でだけ押したことにし、9000 を下回るまで再発火しない。
- 状態機械(方向・同時押し)と名前の表は SDL にもゲームにも依存しない
  `gamepad.h/.cc` に置き、単体で検査できるようにする。SDL の出来事の読み取りと
  「押し → キー」の変換は `windowmanager-sdl.cc` に置く。

## 1. 方向(十字キー・左スティック)

十字と左スティックは**移動専用**(割り当ての対象にしない)。十字が入っていれば
十字を優先し、中立のときだけスティックを見る。

| 向き | 出すキー | ゲーム中 | メニューの中 |
|---|---|---|---|
| 上下左右 | `CK_UP` `CK_DOWN` `CK_LEFT` `CK_RIGHT` | 1 歩 | カーソル移動 |
| 斜め | `CK_HOME` `CK_PGUP` `CK_END` `CK_PGDN` | 斜めに 1 歩 | **縦の成分だけ**(下記) |

- ゲーム中・狙い・地図の画面では矢印キーとテンキー(NumLock 無し)と同じキーなので、
  `bindkey` やキーマップの扱いもキーボードと同じになる。
- メニュー・ポップアップでは、斜めの Home/PgUp などは「先頭へ」「1 ページ」に
  なってしまうので、斜めは縦の成分だけを出す(メニューは縦に並ぶ。スティックを
  少し斜めに倒しても上下に動く)。メニューかどうかは UI の層(`ui::has_layout()`)と、
  いちばん上の層のキーマップ文脈(`ui::current_keymap()`)で見る。狙い(`KMC_TARGETING`)と
  階の地図(`KMC_LEVELMAP`)も UI の層だが、斜めにカーソルを動かせるのでメニューに数えない
  (最初は `has_layout()` だけで見ていて、地図で斜めが縦になっていた)。

### 1.1 斜めの合成とリピート

十字で斜めを押すと、2 つのボタンはわずかにずれて届く。そのまま出すと、
狙った斜めの前に縦か横へ 1 歩出てしまう(ローグライクでは致命的な誤動作)。
変愚の実装は入れ替えの直後に出しているので、ここは変愚より 1 段慎重にした。

| 場面 | 振る舞い |
|---|---|
| 中立 → 上下左右の 1 方向 | **40ms 待つ**(合成の猶予)。その間に 2 つ目が来たら斜めとして出す |
| 中立 → 斜め(同時に届いた) | すぐ出す |
| 猶予の間に離した(短く叩いた) | 叩いた向きを 1 回出す(取りこぼさない) |
| 押し続け | 1 回目のあと `tile_key_repeat_delay`(既定 200ms)待ち、以降 90ms ごと。`tile_key_repeat_delay = 0` ならリピートしない(キーボードと同じ) |
| 1 方向 → 別の向き(曲がる・斜めへ足す) | すぐ出し、リピートの待ちを数え直す(約束 4) |
| 斜め → その成分の 1 方向(片方だけ先に離した) | **出さない**。待ちを数え直し、押し続けたときだけリピートで出す |

- 出すのはゲームが入力を待って `wait_event` を呼んだときだけで、1 回に 1 キー。
  ゲームが重い間に溜まって暴走することはない。
- `wait_event` は、方向を押している間はリピートの時刻までに必ず起きるよう
  待ち時間を縮める。

## 2. ボタン

| ボタン | 名前(rc) | 既定 |
|---|---|---|
| A | `A` | **決定(Enter)。固定** |
| B | `B` | **取消(Esc)。固定** |
| X | `X` | 自動探索 `CMD_EXPLORE`(o) |
| Y | `Y` | 自動戦闘 `CMD_AUTOFIGHT`(Tab) |
| LB | `LB` | 階段を下りる `CMD_GO_DOWNSTAIRS`(>) |
| RB | `RB` | 階段を上る `CMD_GO_UPSTAIRS`(<) |
| LT | `LT` | 所持品 `CMD_DISPLAY_INVENTORY`(i) |
| RT | `RT` | 射撃 `CMD_FIRE`(f) |
| Back(Select) | `Back` | ゲームメニュー `CMD_GAME_MENU`(F1) |
| Start | `Start` | 呪文を唱える `CMD_CAST_SPELL`(z) |
| L3(左スティック押し込み) | `L3` | **マウスの左クリック。固定**(§2.3) |
| R3(右スティック押し込み) | `R3` | **マウスの右クリック。固定**(§2.3) |

LB=下り・RB=上り・LT/RT にコマンドという並びは変愚の既定に合わせた。
X/Y は変愚の「拾う/使う」の代わりに、DCSS でいちばん押す自動探索と自動戦闘にした
(DCSS は自動探索で物を自動で拾う)。Back は変愚では設定メニューで固定だが、
DCSS には設定の画面が無いのでゲームメニューを既定にし、割り当ても変えられる。

### 2.1 コマンドの出し方(キーマップの罠)

変愚の §2.1 と同じ罠が DCSS にもある。`command_to_key(CMD_EXPLORE)` は `o` を返すが、
`o` をそのまま積むと、利用者のキーマップ(`K:` 行・`~` のマクロ編集)で別のキーに
変わりうる。メニューの中で積めば、`o` の品物を選んでしまう。

そこで、**ゲームがコマンドを待っているとき**(`crawl_state.waiting_for_command`、
マウスがコマンドの状態、`ui::has_layout()` が偽)だけ、コマンドを
`encode_command_as_key()` で符号化したキーとして出す。タイル版のマウスの
クリック(`tilereg-dgn.cc`)と同じ道で、キーマップも `bindkey` も通らずに
そのコマンドそのものが実行される。

それ以外の場面(メニュー、ポップアップ、y/n や個数の問い、狙い、地図、--more--)では、
コマンドを割り当てたボタンは**何もしない**(`CK_NO_KEY` を出す)。
変愚の「黙って誤ったキーを積むより無反応が安全」に従う。そこで使えるのは
十字・A・B(と、割り当ての無いボタン。§4)である。

A と B も、コマンドを待っている画面では何もしない。Enter と Esc をそこへ出しても
「そのコマンドは存在しません。」が出るだけで、B で自動探索を止めた直後などに必ず出てしまうため
(実機と同じ道の確認で見つけた)。メニュー・問い・狙い・--more-- では決定と取消になる。

`CK_NO_KEY` は既存の「無視するキー」で、`getch_ck` も `pump_events` も読み捨てる。
何も出さない代わりにこれを出すのは、`kbhit()` と揃えるためである(§2.2)。

### 2.2 自動探索などを止める(`kbhit`)

DCSS は自動探索・移動・休息の最中に `kbhit()`(タイル版は
`wm->next_event_is(WME_KEYDOWN)`)を見て、キーが押されたら止まる。
`next_event_is(WME_KEYDOWN)` はパッドの出来事をその場で状態機械に流し込み、
**パッドが出すキーがあれば真**にする。パッドのどのボタンを押しても止まる
(キーボードと同じ)。押したボタンのキーは、止まったあとに普通に届く。

押しても何も出ない状態(上の `CK_NO_KEY`)でも真にするのは、真なのに次の
`getch_ck` がキーを返さないと、`_getch_mul` が次の入力まで固まるためである。

### 2.3 右スティックと L3・R3(マウスの代わり、2026-10-20 追加)

右スティックはマウスのカーソルを動かし、単独押しの L3・R3 は左・右クリックにする。
タイル版はマウスで地図のマスを選んだり、所持品や呪文の欄を押したりできるので、
パッドだけでもそれが使えるようにする。

- 右スティックの値は `gamepad_state::set_cursor_stick()` で状態機械に持たせ、
  `cursor_motion()` が前回からの移動量を出す。死区は円で 8000、そこから倒し切るまでを
  2 乗の曲線で 1 秒あたり 60〜1400(窓の座標)にする。1 に満たない端数は持ち越す。
  間が空いても 100ms 分しか進めない(重い処理のあとで飛ばない)。
- 倒している間は `ms_until_due()` が 16ms ごとに起こす。`pad_update()` が
  `SDL_WarpMouseInWindow` でカーソルを動かすと、OS から本物のマウスの動きが届くので、
  あとはマウスと同じ道を通る(ツールチップ、地図のカーソルなど)。カーソルの位置は
  `SDL_GetMouseState` だと動きの出来事を読むまで古いので、`SDL_GetGlobalMouseState`
  から窓の位置を引いて出す。窓の外へは出さない。
- 焦点が無いときは動かさない。焦点を失うと倒し方も忘れ、次にスティックが動くまで止まる(約束 1・2)。
- 単独押しの L3・R3 は `pad_click()` が、カーソルの今の位置での
  `SDL_MOUSEBUTTONDOWN` と `SDL_MOUSEBUTTONUP` を `SDL_PushEvent` で積む。
  コマンド待ちかメニューの中かに関わらず、マウスでクリックしたのと同じになる。
  同時押しの層の L3・R3(LB+L3 など)は今までどおり割り当てられる枠。
- 固定かどうかの判定は `pad_slot_fixed()` 1 か所(A・B・L3・R3 の単独押し)で、
  rc・割り当ての画面・pad_binds.txt の読み込みが共通に使う。
- Android には OS のマウスのカーソルが無いので、位置をゲーム側で持つ(§9.2)。

確認の記録(2026-10-20、§6 の 2 つで。実機のパッドは無い):

| # | 見たこと | 結果 |
|---|---|---|
| 1 | 単体検査(`run.py`) | 213 件 PASS(死区・倒し始め・100ms の上限・浅く倒したときの遅さ・焦点・リピートとの重なり、`pad_slot_fixed`) |
| 2 | RX/RY=-32767 を 1.5 秒 → RX=32767 を 350ms → RY=32767 を 300ms | 窓の外にあったカーソルが窓の端に入り、左上の隅 (0,0) で止まり、右へ 456、下へ 411 進んだ。刻みは 11〜22ms(Windows のタイマーの粒) |
| 3 | 2 で自キャラの上に来たとき | タイル版のツールチップ(左クリック 1 ターン待機、右クリック キャラクター概要)が出た |
| 4 | R3 → B → L3 | キャラクター概要(%)が開き、B で閉じ、L3 で 1 ターン待機した(時間 26.3 → 27.3) |
| 5 | rc の `pad_bind = L3:CMD_REST, LB+L3:CMD_REST, R3:CMD_EXPLORE` | L3 と R3 は「can't be rebound」のエラー、LB+L3 は受け付けた |

### 2.4 場面ごとのボタンの固定の役目(2026-10-22 追加)

ボタンに割り当てたコマンドはコマンド待ちのときしか出ないので、狙い・地図・メニューの中では
X や LB を押しても何も起きなかった。そこで、コマンド待ちでない場面では、単独押しのボタンに
場面ごとの固定の役目を持たせる(`_pad_scene`・`_pad_scene_key`。キーボードのキーを出す)。
場面は UI の層のキーマップ(`KMC_TARGETING`・`KMC_LEVELMAP`、それ以外の層はメニュー)と、
層の無い狙い(マウスの状態が TARGET 系)で見分ける。A・B・L3・R3 は場面によらず今までどおり。

| ボタン | 狙い・見回す | 階の地図 | メニュー |
|---|---|---|---|
| LB | 前の相手(`-`) | 下り階段を探す(`>`) | 前のページ(PgUp) |
| RB | 次の相手(`+`) | 上り階段を探す(`<`) | 次のページ(PgDn) |
| X | 説明を見る(`v`) | 自分の位置へ(`@`) | 選択の切り替え(`.`) |
| Y | 届かなくても撃つ(`!`) | — | 全部選ぶ(`,`) |
| LT | — | 前の階(`[`) | — |
| RT | 撃つ(Enter。RT を 2 回で射撃) | 次の階(`]`) | — |

- 複数選択のメニュー(拾う・置く・知識の画面など)で、何も選ばずに Enter(パッドの A)を押すと、
  カーソルの行を選んで確定する(`Menu::process_command`、`InvMenu::process_command`)。
  拾う・置くのメニューは最初の品物にカーソルを置いて開く。店は X で印を付けて A で買う。

## 3. 割り当ての設定(rc オプション `pad_bind`)

```
pad_bind = X:CMD_PICKUP
pad_bind = LT:CMD_DISPLAY_INVENTORY, RT:none
pad_bind = LB+X:CMD_CAST_SPELL, LB+RB+Y:CMD_QUAFF
pad_bind = clear
```

- 右辺は `ボタン:コマンド名` を `,` で並べる。コマンド名は `bindkey` と同じ
  (keybind.txt / `name_to_command`)。メイン画面のコマンド(`CMD_MAX_NORMAL` まで)だけを受け付ける。
  そのうち内部で使うだけの `CMD_NO_CMD_DEFAULT`(キーの割り当てを消す目印)・`CMD_MOUSE_MOVE`・
  `CMD_MOUSE_CLICK`(マウスの処理用)は断る。判定は `gamepad_command_bindable()` 1 か所で、
  割り当ての画面・rc・pad_binds.txt の読み込みが共通に使う(Windows のタイル版で 132 個)。
- `none` で割り当てを外す(そのボタンはマクロのキーになる。§4)。`default` でそのボタンを既定に戻す。
- `pad_bind = clear` で既定の割り当てを全部外す。`pad_bind = default` で全部既定に戻す。
- A・B・L3・R3(単独押し)は固定で、割り当てられない。
- 値は `Options` に持つので、rc を読み直すと既定から組み直される。
- 不正な行は、ほかのオプションと同じくエラーを出して飛ばす。

## 4. 同時押しの層と、マクロのキー

### 4.1 同時押し(LB / RB)

変愚の §10 と同じ。**LB と RB は修飾にもなる。**

- LB・RB を押した瞬間には何も起きない。離したときに、その間に他のボタンを
  押していなければ単独押しとして発火する(LB=下り・RB=上りが使える)。
- LB を押しながら X を押すと「LB+X」、RB とだと「RB+X」、両方だと「LB+RB+X」。
  修飾は「使われた」印が付き、離しても単独発火しない。
- LB+RB の層では LB も RB も単独発火しない。
- 層は 4 つ(単独・LB+・RB+・LB+RB+)。層の中では A と B も割り当てられる
  (固定なのは単独押しの決定・取消・クリックだけ)。修飾自身(LB+LB など)は押しようがないので枠にしない。
- 同時押しにも既定の割り当てを置く(2026-10-22。パッドだけで遊べるように。`gamepad.cc` の
  `pad_chord_defaults`)。LB の層は「動く・拾う・見る」、RB の層は「使う・読む・待つ」に寄せた。
  LB+RB の層と、L3・R3 の同時押しは空き(= マクロのキー)。`pad_bind = LB+X:none` で外せる。

| 枠 | LB+ | RB+ |
|---|---|---|
| X | 休む・探す `CMD_REST` | 1 ターン待つ `CMD_WAIT` |
| A | 拾う `CMD_PICKUP` | 扉を閉める `CMD_CLOSE_DOOR` |
| B | 置く `CMD_DROP` | メッセージの履歴 `CMD_REPLAY_MESSAGES` |
| Y | 階を指定して旅行 `CMD_INTERLEVEL_TRAVEL` | 能力を使う `CMD_USE_ABILITY` |
| LT | 階の地図 `CMD_DISPLAY_MAP` | 薬を飲む `CMD_QUAFF` |
| RT | 見回す `CMD_LOOK_AROUND` | 巻物を読む `CMD_READ` |
| Start | 呪文を覚える `CMD_MEMORISE_SPELL` | スキル `CMD_DISPLAY_SKILLS` |
| Back | キャラクター概要 `CMD_DISPLAY_CHARACTER_STATUS` | ダンジョンの概観 `CMD_DISPLAY_OVERMAP` |

### 4.3 LB・RB を握ったままの方向(2026-10-22 追加)

- LB を握ったままの十字・左スティックは Shift+方向、RB を握ったままは Ctrl+方向になる
  (`pad_output.mods` に握った修飾を付け、`_pad_output_to_key` でキーコードをずらす)。
  ゲームでは走る(`CMD_RUN_*`)・その場で攻撃(`CMD_ATTACK_*`)、狙いでは一直線に撃つ
  (`CMD_TARGET_DIR_*`)、階の地図では 10 マス跳ぶ(`CMD_MAP_JUMP_*`)。
- 方向に使った LB・RB には「使った」印を付ける。以前は印が付かず、LB を握って十字を押した
  あと LB を離すと、単独押しとして階段を下りてしまっていた。

### 4.2 割り当ての無いボタンはマクロのキー

変愚の §9 と同じ考え。**割り当ての無い枠(ボタン×層)は、その枠に固有のキーコードを出す。**
DCSS のマクロ(`M:`)とキーマップ(`K:`)は任意のキーコードをトリガーにできるので、
`~` のマクロ編集でそのボタンを押せばそのまま登録できる。
表も永続化も要らない(登録と保存は DCSS の macro.txt が受け持つ)。

| 決めごと | 内容 |
|---|---|
| キーコード | `CK_PAD_BASE`(-5000)から下へ。単独 X = -5002 …(層×16 + ボタン)。既存のキーコード(内部キー・Alt・Cmd・マウス・コマンド符号)と重ならない範囲 |
| 名前 | `Pad-X`、`Pad-LB+X`、`Pad-LB+RB+Y`。マクロ編集の表示(`keycode_to_name`)と、`bindkey = [Pad-X] ...` などの読み取り(`read_key_code`)の両方 |
| 割り当てが勝つ | コマンドを割り当てた枠はコマンドを出す。マクロを乗せたいときは `pad_bind = X:none` で外す |
| 場面 | どの場面でも出す(メニュー用のキーマップ `K1:` などにも使える)。登録の無いキーコードはゲームが無視する |

## 5. 抜き差しと焦点

- `SDL_INIT_GAMECONTROLLER` は VIDEO|TIMER とは別に `SDL_InitSubSystem` で起こし、
  失敗してもゲームは続ける(パッド無しで今までどおり)。
- `SDL_CONTROLLERDEVICEADDED` で開き(1 本だけ持つ。2 本目は無視)、
  `SDL_CONTROLLERDEVICEREMOVED` で閉じる。開いた・閉じたときは押していた状態を全部忘れる。
- 焦点は `SDL_GetWindowFlags` の `SDL_WINDOW_INPUT_FOCUS` で毎回見る。
  焦点が無ければ押していた状態を全部忘れ、方向は中立を見るまで受け付けない。

## 6. 検査

パッドの実機が無くても確かめられるように 2 つ置く。

1. **単体検査** `ja-tools/gamepad_test/`:`gamepad.cc` だけを cl.exe で組み、
   方向の合成・リピート・ヒステリシス・焦点・再武装、同時押しの状態機械、
   名前の読み書きを機械で確かめる。
2. **実機と同じ道に出来事を流す口**:環境変数 `CRAWL_PAD_TEST` に台本を書くと、
   SDL のタイマーから偽のパッドの出来事(`SDL_CONTROLLERBUTTONDOWN` など)を
   `SDL_PushEvent` で流す。`wait_event` から先は実機と同じ道を通る。
   `CRAWL_PAD_LOG` にファイル名を書くと、パッドが出したキーを 1 行ずつ記録する。
   台本の書き方: 空白区切りで、`500`(500ms 待つ)、`+X` / `-X`(押す/離す)、
   `X`(押してすぐ離す)、`LX=32000` / `RX=20000`(軸の値)、`+Up` などの十字。
   右スティックで動かしたカーソルは `cursor 100,200 -> 122,200`、L3・R3 は
   `L3 -> left click 122,200` の形で記録する。

## 8. 割り当ての画面(2026-10-19 追加)

> ユーザーの問い: 「キー割り当ての UI も作れる?」

DCSS にはオプションを編集する画面が無い(rc を手で書く)。変愚の機能メニューの
キーバインド設定(PAD_KEYBIND_DESIGN.md §5)にならい、ゲームの中で割り当てを変えて
保存できる画面を足す。

### 8.1 入口

- ゲームメニュー(Back / F1 / ~)に「ゲームパッドの割り当て」(P)を足す。
- コマンド `CMD_GAMEPAD_MENU` も足す(ローカルのタイル版だけ。既定のキーは無し)。
  `pad_bind = LB+Back:CMD_GAMEPAD_MENU` や `bindkey` で直接開ける。

### 8.2 画面

1 枚目「ゲームパッドの割り当て」: 枠(ボタン × 層)を層ごとの見出しの下に並べる。
各行は「Pad-X - 自動探索 (o)」。行の頭の Pad-X はその枠のキーをホットキーにしたもので、
**パッドのそのボタンや同時押しを押すとその行の 2 枚目が開く**(どのボタンかを先に選ぶ方式と、
押して選ぶ方式の両方ができる)。割り当てが無ければ「(割り当てなし: マクロのキー)」。
この画面で変えた枠は黄色で出す。単独押しの A・B は固定なので行にしない(下の案内に書く)。

- 十字で選び A で 2 枚目へ。B で閉じる。
- この画面が開いている間だけ、パッドは割り当てに関係なく枠のキー(Pad-X など)を出す
  (捕まえる状態。`gamepad_menu_capturing()`)。単独の A・B と十字は除く。
- 末尾に「この画面での変更をすべて取り消す」。確認は「はい/いいえ」の選択画面で出る
  (メニューの中の yesno は選択画面になるので十字と A で答えられる)。

2 枚目はコマンドの選択で、**2 段に分けてある**(利用者の指示 2026-10-19「選択肢が長すぎ」)。

- 1 段目「X に割り当てるコマンド(今: 自動探索 (o))」: 「割り当てなし(マクロのキー Pad-X を出す)」、
  「元に戻す(rc か既定のまま: …)」、続けて「コマンドの分類」の見出しの下に 7 つの分類を
  「戦闘 (16)」のように数付きで並べる(移動・探索 / 戦闘 / アイテム / 情報 / その他 /
  保存・終了と特別なモード / 方向を指定した移動・攻撃)。全部で 9 行。
- 分類を A で選ぶと 2 段目「X に割り当てるコマンド: 戦闘」が開き、その分類のコマンドだけを
  日本語の名前と今のキー付きで並べる。ここで選ぶと割り当てて両方閉じる。B で 1 段目に戻る。
- 今の割り当ては、1 段目ではそれを含む分類(割り当てなしならその行)、2 段目ではその行を黄色にし、
  カーソルもそこから始める。

割り当てられるコマンドは 132 個(Windows のタイル版)で、全部に名前を付けてある。名前と用語は
`?` のヘルプの訳に合わせた(「アイテム」「装身具」「1ターン待つ」など)。最初の版は 47 個だけに
名前を付け、残り 84 個を `CMD_` の内部の名前で 1 枚に並べていた。内部の名前はふつうに遊んでいて
目にしない(rc の bindkey と keybind.txt だけ)ので全部に名前を付け、続けて 1 枚で 140 行近くあって
長すぎたので 2 段に分けた。表に無いコマンドがあれば(本家で増えたときなど)、最後の分類
「その他のコマンド(内部の名前)」に `CMD_` の名前で並ぶ。

> **罠: タイル版のメニューは、ホットキーを持つ行にしかカーソルの帯を描かない**
> (menu.cc の UIMenu の `me->hotkeys_count() > 0`)。最初は 2 枚目の行にホットキーを
> 付けておらず、操作は効くのに帯が一度も出なかった。押されることの無いキー
> (`CK_PAD_LAST - 1`)をホットキーに持たせ、行の頭の表示(`_get_text_preface`)だけを
> 空白に差し替えた行の型 `pad_choice_entry` で直した。

### 8.3 保存と優先順

- 画面で変えた分は、マクロと同じ場所の `pad_binds.txt` にすぐ書く(1 行 1 枠、

  画面の方が勝つ。画面で「元に戻す」と rc か既定に従う。

## 9. Android の物理パッドとバーチャルパッド(2026-10-21 追加)

Android 版でも、物理のパッドと、画面に重ねるバーチャルパッドを Windows 版と同じ処理
(`gamepad_state`)に流す。

### 9.1 なぜ SDL のパッドを使わないか

- 同梱の SDL は 2.0.7 で、Android のパッドの GUID が機器の識別子そのもの。対応表にもほとんど
  無いので、たいていの機種で `SDL_IsGameController` が偽になり、パッドとして開けない。
- しかも `SDLActivity.dispatchKeyEvent` がすべてのキーを画面のキーボード(`DCSSKeyboard`)へ
  先に回すので、パッドのボタンは SDL のパッドの道まで届かない。
- SDL を上げると `SDLActivity` の改造(CRAWL HACK)を全部移し替えることになるので、上げない。

### 9.2 道

- Java の `DCSSGamepad`(`org.develz.crawl`)が、パッドの機器(`SOURCE_GAMEPAD` か
  `SOURCE_JOYSTICK`)から来たキーと軸を取り分ける。
  - キーは `dispatchKeyEvent` の先頭で。A/B/X/Y、L1/R1、Select(=Back)、Start、
    L3/R3、十字。L2/R2 はキーで来る機種があるので、トリガの軸に直す。
    押し続けの繰り返し(`getRepeatCount() > 0`)は捨てる(繰り返しは C++ の状態機械がやる)。
  - 軸は `SDLGenericMotionListener_API12.onGenericMotion` の先頭で。左スティック、
    トリガ(`AXIS_LTRIGGER`/`AXIS_BRAKE`、`AXIS_RTRIGGER`/`AXIS_GAS`)、十字の HAT
    (`AXIS_HAT_X/Y`。十字のボタンに直す)、右スティック(標準の割り当ての `AXIS_Z`/`AXIS_RZ`。
    その軸が無い機種は `AXIS_RX`/`AXIS_RY`)。変わったときだけ送る。
- JNI の `SDLActivity.nativePadButton(button, down)` と `nativePadAxis(axis, value)`
  (値は SDL_GameControllerButton/Axis)で C++ へ渡す。C++(`windowmanager-sdl.cc`)は
  `which = PAD_INJECTED_ID` の SDL の出来事として `SDL_PushEvent` で積むだけ。検査用の台本
  (§6)と同じ道なので、`wait_event` から先は Windows 版と同じになる。
- 右スティックのカーソルと L3・R3 のクリックは Windows 版と同じに働く。ただし Android には
  OS のマウスのカーソルが無いので、カーソルの位置は `windowmanager-sdl.cc` が持つ
  (`_pad_cursor_x/y`)。触れたとき・マウスの出来事が来たときはその位置に合わせ、まだ一度も
  触れていなければ画面の真ん中から始める。右スティックでは `SDL_WarpMouseInWindow` の代わりに
  `SDL_MOUSEMOTION` を自分で積む。盤面ではマウスを乗せたときと同じカーソルの枠が出る。

### 9.3 バーチャルパッド

- Java の View(`DCSSVirtualPad`)を、画面のキーボードの上に重ねる。Canvas で描き、
  ボタンの外に最初の指が触れたときは受け取らずに下の画面へ素通りさせる。
- 置くのは左スティック(8 方向。十字のボタンとして送る)、右スティック(連続値。半径の
  0.30 までは中立で、外側を C++ の死区 8000 から倒し切りまでに写す)、A/B/X/Y、LB/RB、LT/RT、
  L3/R3、Start/Back。
- 配置と大きさは変愚蛮怒 HD2D のバーチャルパッド(`hd2d/ui/virtual_pad.cpp` の
  `kDefaultsLand`/`kDefaultsPort`。実機で詰めた比率)を借りた。横長と縦長で別の表。
  スティックの入りと出は半径の 0.34 と 0.22(ヒステリシス)。
- 一度掴んだボタンは指を滑らせても替えない。スティックだけ向きを追う。複数の指を受ける。
- 出すかどうかは起動画面の「バーチャルパッド」(設定 `virtual_pad`、既定は出さない)。

### 9.4 画面のキーボードとの関係

- 「パッドの画面」= バーチャルパッドを使う設定か、物理のパッドが繋がっている。
- パッドの画面では、ゲームの始め(`jni_keyboard_control(1)`)に画面のキーボードを出さない。
  文字を入れたいときは、ゲームメニューなどのキーボードの切り替え(`jni_keyboard_control(2)`)で出す。
- バーチャルパッドは、キーボードを出していないときだけ出す。物理のパッドが繋がっていれば出さない。
- 物理のパッドの抜き差しは `InputManager.InputDeviceListener` で見る。繋がったらキーボードを隠す。
  繋がっていると分からない機器でも、パッドの入力が来た時点でパッドの画面にする。

## 10. メッセージ欄の問いをカーソルで答える(2026-10-21 追加)

パッドの十字は矢印キーを出すが、メッセージ欄で 1 文字を待つ問いでは矢印が役に立たなかった
(催促がくり返し出る、無視される、中止になる)。能力値の上昇は大文字の S/I/D しか受け付けず、
パッドだけでは先へ進めなかった。

- 共通の関数 `prompt_choose_key`(prompt.cc)。選択肢を `PromptMenu` で出す。`prompt_menu` が
  真(タイル版の既定)ならポップアップのメニューで、カーソルと A(Enter)で選べ、キーも
  そのまま効く。偽ならメッセージ欄に出す。
  - 置き換えた問い: 能力値の上昇(大文字だけを求めるときはカーソルを置かずに出す)、
    キー割り当ての変更(`=`)の最初の問い、カードを 3 枚から選ぶ、Gozag の薬の購入と
    商人への投資、祖霊の性別、仲間への命令(`t`)。
- 1 文字の問いのまま、カーソル(と Enter)で一覧のメニューを開くようにしたもの:
  装備の付け替え(外す品物を選ぶ)、呪文を唱える(唱え直しが無いときの Enter も)、
  品物を選ぶ問い(メッセージ欄に戻ったとき)。
- y/n の問い(`yesno`)は、メッセージ欄で訊いている最中にカーソルが来たら、はい/いいえの
  ポップアップに切り替える。店の購入・アイテムの取得・カードの並べ替えのように、メニューの
  more の行で訊くもの(問いの文を渡していない)は、新しい引数 `cursor_popup` に問いの文を渡す。
  キーボードで遊ぶときの見た目は変わらない。
- 数の問いは、上下で ±1、PgUp・PgDn で ±10、範囲の中で数を増減する(`msgwin_get_line` の
  `number_lo`/`number_hi`)。ポップアップではホットキーの処理で、メッセージ欄では
  `line_reader` の派生 `number_line_reader` で受ける。範囲を渡したのは、拾う個数(`;`)、
  タイル版の Ctrl+クリックで拾う・置く個数、階の注釈の階。最初のキーが上下なら 1 か最大から
  始める。最初のキーが文字でないときに入力欄へ制御文字を入れていた不具合も直した。
- 旅行先の階の問いは、上下で 1 つ浅い階・深い階へ(`<`・`>` と同じ)。
- 品物と地形の説明のポップアップでは、Enter(パッドの A)で、下の行にある操作(読む・手に持つ・
  置く・上る など)をカーソルで選ぶメニュー(見出し「どうしますか？」)を開く(2026-10-22 追加)。
  今までは Enter で説明を閉じていた。操作の行の後ろには「(Enter で一覧から選ぶ)」を添える。
  操作の英文(「(w)ield」など)は `_action_strings`・`_feat_action_strings` に分け、括弧の中を
  キーに、訳文から先頭の「(w)」を外したものを名前にする。
- 所持品の一覧(`i`、パッドの LT)は、最初の品物にカーソルを置いて開く。パッドでは
  LT → A(説明)→ A(操作のメニュー)→ A で、マウスで品物を押したときと同じことができる。
- 方向キーはどの問いでも今まで役に立っていなかったので、キーボードでも同じように効く。

- 「yes」と打たせる確認(`confirm_prompt`。金庫に鍵なしで入る、ルーンを残して出る、罠に入る
  など)は、カーソルか、何も打たずに Enter なら、はい/いいえを 2 回訊く(2 回目は「本当に
  よろしいですか？」)。わざと手間をかける確認なので、1 回では決まらないようにした(2026-10-22)。
- 祭壇で今の神を捨てる確認は大文字の Y だけを受け付けていたので、A(Enter)では
  はい/いいえのポップアップで訊く(2026-10-22)。

- 文字の入力欄(メッセージ欄の `line_reader` と、ポップアップの `ui::TextEntry`)を使って
  いる間は、Y で文字を選ぶメニュー(a〜z・0〜9・空白・`-`・`.` の格子。`pad_pick_char`)を開き、
  A で 1 文字ずつ入れて B で閉じる。X は 1 文字消す(Backspace)。入力欄が使われているかは
  `text_input_begin`/`text_input_end`(`line_reader::read_line` の間と、`TextEntry` に焦点が
  あるとき)で数える。日本語は入れられない(2026-10-22)。
- 調べもの(`?/`)の名前の問いは、何も入れずに Enter なら、その種類の全部を一覧にする(今までは
  取り消しだった)。
- ヘルプは、Enter(A)で章をカーソルで選ぶメニューを開く。章の一覧は最初の画面の文
  (`<w>?</w>: 名前` の行)から作る。
- スキルの画面は、スキルの最後の行から下で、下の段のボタンとスイッチ(?・=・-・/・|・*・_・!)
  へ行ける。左右でたどり、上でスキルへ戻る(`SkillMenu::set_links`)。目標値の入力では、上下で
  ±1.0、PgUp・PgDn(パッドの LB・RB)で ±0.1。
- 起動画面で Esc(パッドの B)を押すと、ゲームを終える前に確かめる。
