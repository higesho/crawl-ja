# 立体化(変愚蛮怒 HD2D 方式)の検討

最終更新: 2026-10-21。

**決めたこと(2026-10-21、利用者)**: このリポジトリは原作の日本語化として続ける。
HD2D へのコアの取り込みは、変愚の側で検討する。この文書は、そのための材料として残す。

変愚蛮怒の HD2D(`C:\Project2\hengband-3.0.2.3-Beta`)のように、DCSS を立体で遊べるようにする道を比べた。
HD2D 側には DCSS をコアにする調査がすでにある(`docs/DCSS_CORE_STUDY.md`、2026-10-06。原作 0.34.1 を対象)。
この文書は、それに **この日本語版フォーク(crawl-ja)を原作として使う** という条件を足して見直したもの。

## 1. 結論

- **勧めるのは (A): HD2D の新しいコア「DCSS コア」として載せる。**原作の代わりにこのフォークを使う。
  - HD2D の調査で「いちばん重い」とされた日本語化(DCSS_CORE_STUDY §5.1)は、このフォークで済んでいる。
    ゲームが出す文はもう日本語なので、HD2D には訳した後の文字列を渡すだけでよい。
  - フォークなので、原作に手を入れられないという縛りが無い。演出の出来事を送る手入れ(§3.6)を、
    気兼ねなく足せる。
  - 立体の描画(ボクセルの地形、光と影、カメラ、XR、Android)は HD2D にもうある。DCSS の側で作り直す必要は無い。
- **(B): DCSS のタイル版の中を立体にする道は勧めない。**
  - タイル版の描画は、昔の OpenGL(固定機能)の正射影で、2D の前提が深い(`glOrtho`、四角形だけの
    `GLShapeBuffer`、テクスチャごとに描く順で重なりを決める作り)。地図だけ新しい描画を書き直すことになり、
    推測で数千行。上流を取り込むときにもぶつかりやすい。
  - そのうえ、できあがるのは HD2D が持っている機能の一部の作り直しになる。

## 2. 2 つの道の比べ

| 項目 | (A) HD2D のコア | (B) タイル版の中で立体化 |
|---|---|---|
| DCSS 側の仕事 | 画面の層を 1 本足す(コンソール版の `libw32c.cc` の代わり)+フレームの組み立て | 地図の描画を GL 3.3 で書き直し、マウスでマスを選ぶ処理も作り直す |
| HD2D 側の仕事 | コアの登録 1 行、地形の名寄せ表、DCSS の絵の板、必要ならプロトコルの欄 | 無し |
| 見た目 | ボクセルの地形・光と影・カメラ回転・一人称・XR が最初から使える | 作った分だけ |
| 日本語 | フォークの訳がそのまま出る | そのまま |
| 操作 | HD2D の UI(パッド中心)。タイル版のマウス中心の UI は使えない | タイル版のまま(マウス・パッド・ホイール) |
| 配布 | HD2D の配布物に DCSS コアの exe を足す | crawl-ja の配布物のまま |
| 上流との衝突 | 画面の層は別ファイルなので小さい | 大きい |

## 3. (A) の設計の案

### 3.1 繋ぎ方

- HD2D の画面側がコアを子プロセスとして起動し、stdin と stdout の無名パイプで話す。
  形式は「u32 リトルエンディアンの長さ+UTF-8 の JSON」で、主導はコア(HD2D の `hd2d/net/core_link.cpp`、
  仕様は `C:\Project2\roguelike-next\docs\CORE_PROTOCOL_V1.md`)。
- DCSS の画面の関数は `libconsole.h` に集まっている(`getch_ck`、`kbhit`、`cgotoxy`、`putwch`、`cprintf`、
  `textcolour`、`update_screen` など)。コンソール版で `libw32c.cc` の代わりに `libhd2d.cc` を組めば、
  ゲームの本体はそのまま動く。Umoria で `ui_io.cpp` を差し替えたのと同じ形。
- このフォークの `MSVC/crawl.vcxproj` には `Release Console|x64` の構成がある。そこにコア用の構成を 1 つ足す。
  - 未確認: HD2D の他のコアは同梱の clang(i686)で組んでいる。パイプの約束を守れば MSVC の x64 で組んだ exe でもよいか。
- ブラウザ版の `tileweb.cc` は手本として読むだけにする。通信路が Unix のソケットで、Windows ではそのまま組めないため。

### 3.2 フレームの組み立て

- 地図は `env.map_knowledge`(80×70 の `map_cell`)から組む。地形・罠・雲・アイテム・`monster_info` を種類の値で取れるので、
  端末の字を読む必要は無い。
  - 見えている: `MAP_VISIBLE_FLAG`。覚えている: `MAP_SEEN_FLAG`。魔法の地図: `MAP_MAGIC_MAPPED_FLAG`。
- マスや実体の値の取り方は、`tileweb.cc` の `_send_cell`・`_send_monster`・`_send_player` を手本にする。
- 返事のフレームは、キーを読んだ後の画で出す。Angband のコアで 3 回つまずいた罠(DCSS_CORE_STUDY §4.2)。

### 3.3 地形の名寄せ

- HD2D に送る `terrain_id` は変愚の地形番号。DCSS の 221 種を、変愚の番号と予約した範囲に写す表が要る。
- 重いのは、神の祭壇 29 種と、ポータル・枝の出入口(入る側 41 種・出る側 42 種)。予約した範囲で
  「祭壇」「入口」「出口」の 3 つにまとめ、見分けは色か看板の板で付けるのが軽い(案)。
- 変愚に無い地形(樹木 4 種、ケース、転送装置、毒沼、泥など)はプレハブを足す。
- アビスは地形が動き続けるので、ボクセルの地形を組み直す時機を決める必要がある。

### 3.4 絵(怪物・アイテム・プレイヤー)

- rltiles の PNG(約 8 千枚。大半が CC0)を、HD2D の `tools/voxel/tile_to_slab.py` で板にする。
  絵を作り直さずに済むのが大きい。配る前に、1 枚ごとの来歴を `github.com/crawl/tiles` で確かめる。
- 1 マス 1 枚に収まらない絵がある(ゾンビ・骸骨の重ね、ドラコニアン、武器を持った怪物、装備を重ねた
  プレイヤーの人形)。次のどちらか。
  - コア側で合成した絵の索引を出す(合成の組み合わせごとに索引を振る)。
  - プロトコルに「重ねる板」の欄を足す(HD2D 側の作業。マスの情報の印の欄はもう満杯)。

### 3.5 メニューと文字だけの画面

HD2D の Angband で課題の大半を占めたのは、地図ではなくメニューと問い(誕生・店・知識・文字入力・`-more-`)だった。
2 段で進めるのがよい。

1. **端末の写しで全部を遊べるようにする。**コンソール版は所持品・説明・キャラクター作成・メニューを
   すべて文字で描く。それを HD2D の `menu_term_lines` に流せば、最初から全画面が出る。
   入力待ちの種類は `mouse_control::current_mode()` で分かる(コマンド待ち・狙い・`-more-`・はい/いいえ・文字入力)。
2. **よく使う画面から、構造化した窓(`ModernWindow`)に移す。**所持品、店、キャラクター作成、
   アイテム・モンスターの説明の順。手本は `menu.cc`・`ui.cc`・`describe.cc` の `#ifdef USE_TILE_WEB` の部分。

### 3.5.1 UI の元をどこから取るか(案)

HD2D の UI はパッドが基準で、DCSS のタイル版(マウスが基準)とも、コンソール版(文字が基準)とも違う。
どこから画面の中身を取るかで、HD2D 側の作りが大きく変わる。

| 元 | 取れるもの | 向き不向き |
|---|---|---|
| コンソール版の文字(§3.5 の 1) | 全画面の文字と色 | すぐ全部出るが、見た目は端末のまま。構造は字から読み取るしかない |
| ウェブタイル版の JSON(`tileweb.cc` など) | メニューの項目(ホットキー・色・タイル)、説明のポップアップ 15 種(`ui-push`)、キャラクター作成の選択肢、地図のマスの重ねるタイル(人形・合成の絵を含む) | 構造がそろっている。§3.4 の合成の絵の問題もこちらで片付く。ただし通信路が Unix のソケットで、コンソールの層が curses。Windows で組むには通信の 4 関数(`initialise`・`finish_message`・`_receive_control_message`・`await_input`)をパイプに替え、curses の層も替える |

- 案: **ウェブタイル版の JSON を元にし、アダプタで HD2D のフレームに写す。**DCSS 側で UI を構造化し直す
  仕事が要らなくなる。HD2D 側では、ポップアップ 15 種とメニューを `ModernWindow` に写す表を作ることになる。
- 操作: DCSS は全部の操作がキーで足りる。パッドは HD2D のコマンド表(`pad_commands`)でキーに訳せばよい。
  地図のクリックで歩く操作は、ウェブタイル版の `click_cell` を HD2D の `map_click` に写せる。
- このフォークで足したパッド対応(`gamepad.cc`)は、ローカルのタイル版のものなので、HD2D では使わない。

### 3.6 演出(魔法の弾・爆発)

- DCSS はビームや爆発をターンの途中で描いて待つ(`bolt::draw`、`bolt::explode`、`flash_view`、
  `animation_delay`)。外から見えるのは重ねたタイルと色だけで、弾の始点・終点・種類は出てこない。
- このフォークの中で、`bolt::draw`・`bolt::explode` から HD2D の `projections`(形・経路・属性の名前)を
  送るように足す。原作に手を入れない縛りが無いので、これが素直。
- 最初の段では `use_animations` を切って、結果だけで遊べるようにしておく。

### 3.7 そのほか

- 保存先: 初回起動で説明文の SQLite と地形の型の索引を書く。`-dir` か `CRAWL_DIR` で HD2D のデータの下を指す。
- 組み立ての前処理(Perl・Python によるヘッダの生成、`tilegen`)は、このフォークの Windows 版でもう回っている。
- 終了は `end()` から `exit()`。Android で 1 プロセスに入れるなら、他のコアと同じく差し替えが要る。

## 4. 段階の案

| 段 | 中身 | できあがり |
|---|---|---|
| M0 | `libhd2d.cc` で起動・終了・キー入力・端末の写しだけを通す | HD2D の中で、文字の画面のまま DCSS が遊べる |
| M1 | 地図のフレーム(地形の名寄せの仮の表、見えている/覚えている、プレイヤーの位置) | ボクセルのダンジョンの中を歩ける |
| M2 | 怪物とアイテムの板(rltiles から)、HUD、メッセージ | 立体で戦える |
| M3 | 所持品・店・キャラクター作成・説明を構造化した窓に。パッドのコマンド表 | パッドで一通り遊べる |
| M4 | 演出(`projections`)、合成の絵、祭壇・ポータルの見た目、アビス | 見た目の仕上げ |

アダプタの大きさは、これまでのコアから見て 1.5〜2 万行(Angband 約 1.9 万行、Frox 約 2.1 万行)の見込み。
ただし日本語化の分が要らないので、Angband より軽くなる見込み(推測)。

## 5. 残っている判断(変愚の側で)

- アダプタは HD2D 側(`tools/<コア>/`)に置き、このフォークを原作として取り込む形になる(2026-10-21 の決定から)。
  このフォークに手を入れるのは、日本語化に役立つものか、HD2D 以外でも害の無いものに限るのがよい。
- UI の元を、コンソール版の文字にするか、ウェブタイル版の JSON にするか(§3.5.1)。
- M0 だけ先に作ってみるか。つなぎの部分が動くかを確かめられ、規模の見積もりも確かになる。
