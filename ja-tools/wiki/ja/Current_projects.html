0.35 更新プロジェクト trunk で入る予定の変更について、当てはまるところに Template:CBA をつける(CBA は Crystal Ball Articles の略。これから trunk に入るゲームの変更を書きとめるのに使う)。

CBA が GitHub の特定のコミットを指しているときは、CBA テンプレートの中で Template:Commit ref‎ を使ってそのコミットを参照する:

  • <ref>{{commit ref|Commit Hash|Game Version|Title of Reference}}</ref>

今回の開発サイクルで機能が凍結されたら、0.35 更新プロジェクトを参照。

足りないページ Special:WantedPages、Special:WantedTemplates、Special:WantedFiles、Special:WantedCategories。ページがまだ存在しないものにリンクしていると、ここに載る。これらの一覧を空に保つのが目標だ! 全員 継続中
古くなった CBA の更新 Category:Outdated_Crystal_Ball_Articles。これらの記事には(ページの変更履歴の節に){{CBA}} テンプレートがある。このテンプレートは、これから trunk に入るゲームの変更を書きとめるためのものだ。すでにリリースされたバージョンについては、その変更がもう記事に反映されているか確かめる(モンスターの能力値の変更のように、自動で反映されていることもある)か、変更に合わせて記事を更新する。CBA の部分は、変更履歴の項目として書き直す。ふつうは過去形で、たとえば Prior to version 0.XX this was ... のように書く。 全員 継続中

引き受け手募集中のアイデア

プロジェクト 目標 状況
能力値の変更を自動で抽出 Reddit のユーザー kibwen のコメントより: 「新しいリリースのたびに wiki を更新し続けなくて済むようにする方法の一つは、ゲームのソースから情報を自動で抜き出す姉妹サイトを作ることだ。モンスターの能力値、アイテムの説明、呪文の一覧など、ゲーム内の ?/ 検索で出せるものならほぼ何でもいい。そういうデータベースなら、1バージョンあたりに要る容量はごくわずか(たぶん 1MB 未満)だろうし、JSON のインターフェースがあれば、wiki の情報ボックスのようなものをそこから作ることもできる(もちろん、それ自体の Web インターフェースを持たせてもいい)。」 実現できるか、役に立つかについての意見を「議論」タブで募集中。
